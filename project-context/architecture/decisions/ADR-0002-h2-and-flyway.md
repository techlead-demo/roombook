# ADR-0002 H2 file database with Flyway migrations

Status: accepted

## Context
The app must run on a developer machine and in CI without Docker or a database server.

## Decision
- H2 in file mode (`backend/data/roombook`, git-ignored) for local runs; in-memory H2 for tests (profile `test`) and Playwright (profile `e2e`).
- The schema and reference data (users, rooms) are created only by Flyway migrations in `backend/src/main/resources/db/migration/`. Hibernate runs with `ddl-auto=validate`.
- Migrations are append-only: once merged, a migration is never edited; changes go in a new `V<n>__<description>.sql`.

## Consequences
- Use SQL that H2 accepts (standard SQL; `GENERATED BY DEFAULT AS IDENTITY` keys).
- After switching to a branch whose migrations differ, delete the local file database (`make reset-db`).
